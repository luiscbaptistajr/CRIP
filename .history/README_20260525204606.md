> Close more deals, retain more customers, grow more revenue.

CRIPs (Customer Relationship Intelligence Platform) is a modern, AI-powered Customer Relationship Management platform built for fast-moving sales teams and customer success organizations. It centralizes your pipeline, automates busywork, and surfaces the insights you need to act before opportunities slip away.

## Features

### Core CRM

- **Contact & Company Management** — Unified profiles with activity timelines, tags, and custom fields
- **Deal Pipeline** — Drag-and-drop Kanban boards with configurable stages, weighted forecasting, and close-date tracking
- **Task & Activity Tracking** — Log calls, emails, meetings, and notes with automatic association to contacts and deals
- **Lead Scoring** — Rule-based and ML-assisted scoring to prioritize high-intent leads

### AI & Automation

- **Smart Follow-up Suggestions** — AI surfaces stale deals and recommends next actions
- **Email Sentiment Analysis** — Understand the tone of customer communication at a glance
- **Workflow Automation** — Trigger sequences, assignments, and alerts based on pipeline events
- **Predictive Churn Detection** — Early-warning signals for at-risk accounts

### Collaboration

- **Team Inbox** — Shared email inbox with assignment, snoozing, and internal notes
- **Role-based Permissions** — Fine-grained access control per team, region, or record type
- **Activity Feed** — Real-time stream of all team actions on shared accounts

### Reporting & Analytics

- **Revenue Dashboards** — MRR, ARR, churn rate, and cohort analysis out of the box
- **Pipeline Velocity Reports** — Understand how quickly deals move through each stage
- **Custom Report Builder** — Drag-and-drop query interface with CSV/PDF export
- **Goal Tracking** — Set quota targets per rep, team, or time period

## Quick Start

Get a local development environment running in under five minutes.

```bash
# 1. Clone the repository
git clone https://github.com/your-org/crip.git
cd crip

# 2. Install dependencies
npm install

# 3. Copy environment template
cp .env.example .env.local

# 4. Start the database (requires Docker)
docker compose up -d postgres redis

# 5. Run database migrations
npm run db:migrate

# 6. Seed with demo data (optional)
npm run db:seed

# 7. Start the development server
npm run dev
```

Open `http://localhost:3000` and sign in with the default admin credentials:

| Field    | Value            |
| -------- | ---------------- |
| Email    | admin@crip.local |
| Password | changeme123!     |

> **Note:** Change the default credentials immediately. They are only valid in development mode.

## Configuration

CRIP is configured through environment variables. Copy `.env.example` to `.env.local` for local development or inject variables directly in production.

### Required Variables

```env
# Database
DATABASE_URL=postgresql://user:password@localhost:5432/crip

# Redis
REDIS_URL=redis://localhost:6379

# Auth
NEXTAUTH_SECRET=your-secret-here
NEXTAUTH_URL=https://your-domain.com

# App
NEXT_PUBLIC_APP_URL=https://your-domain.com
```

### Optional Services

```env
# Email (SMTP)
SMTP_HOST=smtp.postmarkapp.com
SMTP_PORT=587
SMTP_USER=your-smtp-user
SMTP_PASS=your-smtp-password
EMAIL_FROM=noreply@your-domain.com

# AI features (OpenAI)
OPENAI_API_KEY=sk-...

# File Storage (S3-compatible)
S3_BUCKET=crip-uploads
S3_REGION=us-east-1
S3_ACCESS_KEY=...
S3_SECRET_KEY=...

# Analytics
POSTHOG_KEY=phc_...
```

See [Environment Variables](#environment-variables) for the full reference.

## Architecture Overview

CRIP is a Next.js monolith with a clear separation between the web layer, business logic, and data layer.

```
crip/
├── app/                  # Next.js App Router (pages, layouts, API routes)
│   ├── (auth)/           # Sign-in, sign-up, SSO flows
│   ├── (dashboard)/      # Core app: contacts, deals, reports
│   └── api/              # REST + tRPC endpoints
├── server/               # Server-side business logic
│   ├── db/               # Drizzle ORM schema and migrations
│   ├── services/         # Domain services (deals, contacts, email)
│   ├── jobs/             # Background workers (BullMQ)
│   └── ai/               # LLM integrations and prompt templates
├── components/           # Shared React UI components
├── lib/                  # Utilities, constants, type helpers
├── public/               # Static assets
└── tests/                # Unit, integration, and e2e tests
```

### Tech Stack

| Layer       | Technology                        |
| ----------- | --------------------------------- |
| Frontend    | Next.js 14, React 18, Tailwind    |
| API         | tRPC, REST (for webhooks/public)  |
| Database    | PostgreSQL + Drizzle ORM          |
| Cache/Queue | Redis + BullMQ                    |
| Auth        | NextAuth.js (OAuth + credentials) |
| AI          | OpenAI GPT-4o via Vercel AI SDK   |
| Email       | Nodemailer + React Email          |
| Storage     | S3-compatible (Tigris, AWS, R2)   |
| Testing     | Vitest + Playwright               |

## API Reference

CRIP exposes a RESTful API for external integrations. All endpoints are under `/api/v1/` and require a Bearer token.

### Authentication

```bash
curl -X POST https://your-domain.com/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "••••••••"}'
```

Returns a `{ token, expiresAt }` object. Pass the token as `Authorization: Bearer <token>` on subsequent requests.

### Key Endpoints

| Method | Endpoint                   | Description                 |
| ------ | -------------------------- | --------------------------- |
| GET    | `/api/v1/contacts`         | List contacts (paginated)   |
| POST   | `/api/v1/contacts`         | Create a contact            |
| GET    | `/api/v1/contacts/:id`     | Get a single contact        |
| PATCH  | `/api/v1/contacts/:id`     | Update contact fields       |
| DELETE | `/api/v1/contacts/:id`     | Archive a contact           |
| GET    | `/api/v1/deals`            | List deals                  |
| POST   | `/api/v1/deals`            | Create a deal               |
| PATCH  | `/api/v1/deals/:id`        | Update deal stage / fields  |
| GET    | `/api/v1/reports/pipeline` | Pipeline summary            |
| POST   | `/api/v1/webhooks`         | Register a webhook endpoint |

Full API documentation is available at `/api/docs` (Swagger UI) when running in development mode, or at [docs.crip.io](https://docs.crip.io).

### Webhooks

CRIP can send real-time event payloads to any HTTPS endpoint you register.

Supported events: `contact.created`, `contact.updated`, `deal.stage_changed`, `deal.won`, `deal.lost`, `task.completed`

```json
{
  "event": "deal.stage_changed",
  "timestamp": "2025-03-14T10:22:00Z",
  "data": {
    "dealId": "deal_01j...",
    "from": "proposal",
    "to": "negotiation",
    "changedBy": "user_01j..."
  }
}
```

## Deployment

### Vercel (Recommended)

CRIP is optimized for Vercel deployment with zero-config setup.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/your-org/crip)

Set all required environment variables in the Vercel dashboard before deploying.

### Self-Hosted (Docker)

```bash
# Pull and start all services
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d

# Run migrations after first boot
docker compose exec app npm run db:migrate
```

The `docker-compose.prod.yml` includes CRIP, PostgreSQL, Redis, and an Nginx reverse proxy.

### Kubernetes

Helm chart available at `deploy/helm/crip`. See `deploy/helm/README.md` for values reference and upgrade instructions.

## Contributing

We welcome contributions of all sizes — bug fixes, new features, documentation improvements.

### Development Setup

```bash
# Fork and clone the repo, then:
npm install
cp .env.example .env.local
docker compose up -d postgres redis
npm run db:migrate
npm run dev
```

### Workflow

1. Open an issue describing the problem or feature.
2. Fork the repo and create a branch: `git checkout -b feat/your-feature`.
3. Write code and tests. Run `npm run test` and `npm run lint` locally.
4. Submit a pull request against `main`. A maintainer will review within 48 hours.

### Code Style

- TypeScript strict mode is enabled. No `any` without a comment explaining why.
- Components use functional style with named exports.
- Business logic lives in `server/services/`, not in route handlers.
- All database queries go through the Drizzle ORM — no raw SQL in application code.
- Run `npm run format` (Prettier) before committing.

See `CONTRIBUTING.md` for the full guide, including our commit message conventions and release process.
